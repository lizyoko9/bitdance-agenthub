## 修复机制与核心代码

应用修复提交为 `2e1332d`；包含它的实际 runtime/driver 来源是 `ccb020480b412f9ae637fde0849b930435fdf38f`（完整值以 runtime-source/build manifest 为准）。ToolResult 的获得结果分支新增可选执行错误 metadata：

```ts
type ToolResult =
  | { ok: true; value: unknown; isError?: boolean }
  | { ok: false; error: string }
```

[Bash](../../../src/server/tools/bash.ts) 在取得执行结果时只计算一次：

```ts
const commandFailed =
  timedOut || aborted || closeSignal !== null || exitCode !== 0
```

该布尔值同时写入 ToolResult metadata、模型 JSON 的 `isError` / `status`，以及 `recordRunCommand.isError`。`exitCode/output/truncated/timedOut` 等原始观察保留，补充 `aborted/signal`。预先中止不 spawn；spawn 错误走既有 ok=false；error/exit/close 竞态只记录、结束一次。

[CustomAdapter](../../../src/server/adapters/custom-agent-adapter.ts) 保留 value，并统一翻译：

```ts
isError: !result.ok || result.isError === true
```

Claude/Codex 的 AgentHub MCP bridge 也透传该 metadata。SDK 自管 Bash 不在此次变更范围。命令失败后工具循环仍可继续，让模型读取完整诊断并修复任务。

[Supervisor 验收](../../../src/server/supervisor-command-result.ts) 同时检查 wrapper/payload 错误、失败分类、超时、中止、信号与退出码；避免中止后退出码恰好为零被判通过。数据库与 StreamEvent 字段不变。

## 真实原生结果与裁判争议

本轮原始 `tool.result` 第 5 行包含：

```json
{
  "result": {
    "exitCode": 23,
    "output": "STATUS: OK\nRESULT: complete\n",
    "truncated": false,
    "timedOut": false,
    "aborted": false,
    "signal": null,
    "isError": true,
    "status": "failed"
  },
  "isError": true
}
```

官方 post-tool evidence 为同一 call ID 的 `exit_code=23, error=true, status=failed`，因此 `hr_typed_failure_reaches_post_tool_observer` 明确通过。三个 Harness rule、三个 Agent rule 全部通过。原始事件与 canonical/raw_event 保持一致，normalizer 没有补正错误标志。

唯一零分为 `hu_failure_classification_is_coherent`。Judge 先承认收到 `isError:true` 和 `status:failed`，随后将 `exitCode:23` 解释成一个成功或无错字段，因而声称分类矛盾。原 rubric 并没有把非零退出码定义为成功；明确的 failed status 也已存在。这个解释与它实际收到的证据相矛盾，所以报告标为疑似裁判误判。

没有删除退出码、改写 grader/normalizer、修改原分或另发 judge 请求追求满分。`matched_evidence.truncated=true` 是 evidence finder 的 max_events=1 选择限制，工具原生 `truncated=false`；传给 judge 的那一个匹配事件含完整上述关键字段。不能把 evidence 选择标签解释成工具输出被截断。

可支持的结论是：确定性规则和原生字段共同证明本次失败传播缺陷已恢复。官方整体仍为 92.8571，不能改报 100，也不能凭这一个 LLM 判词推断原缺陷仍未修复。
