# Spec 17 — 可复用交付校验

在对话顶部点击 **交付校验**。先在对话里写清交付条件，再新建规则，选择对应的用户消息、要检查的文件和本会话中的 Custom Agent。可以选同一消息里的多个原文片段。文件用工作区相对路径，例如 `output/report.json`。

点击生成草稿后，框架登记一个专用 Custom 运行，从原文和输入别名生成检查草稿。它复用所选 Agent 的模型配置。单次生成最多一次模型请求、4096 输出 tokens、45 秒，SDK 重试为零。只发送选中的原文、别名、格式和校验语法。生成用途不继承历史、附件、Skills 或工具权限。

核对每条检查对应的用户要求。纯函数启用前需要审阅并实际执行通过和失败样例。框架解释纯函数的结构化定义，例如 `equals(count(rows), add(summary.deleted, summary.kept))`。v1 支持文件存在、JSON 类型和字段约束、Markdown ATX 标题、布尔组合、计数、求和、等值以及有界的逐项断言。表达式只能访问命名的快照内容。文件读取由服务端负责，每次最多 8 个文件、每文件 256 KiB、合计 1 MiB，拒绝符号链接、硬链接、非普通文件和不稳定读取。

选中已启用的精确版本，点击 **校验当前文件**。框架读回文件并执行保存的规则。复验无需模型请求。修订时可从已保存版本复制需求和输入绑定并生成下一版。旧版本继续按原需求和范围约束引用，需求修改、工作区重绑、引擎不兼容或停用会使该版本无法使用。

回执展示校验时间、规则版本、文件哈希、每条检查状态及失败位置。缺失必需规则、无法读取的快照或不支持的要求标为未验证。历史记录只对应当时读取的快照，改文件后可再次复验。运行结束和交付验收状态分别记录。

SQLite 启动时建 `delivery_validation_revisions` 和 `delivery_validation_receipts` 两张表。使用现有本地数据库，应用重启后可选取保存的版本。表内保留需求引用、规则及函数、确认的样例、生成运行、版本和回执，校验读取的文件正文留在工作区。清空历史时一并清除该会话的规则与回执。会话删除通过外键级联清理。

API 路径为 `/api/conversations/[id]/delivery-validation`。GET 返回同会话的用户来源、可用 Custom Agent 和已保存版本，来源选择器默认展示最近 50 条用户消息。已保存版本修订可带入旧的引用并由服务端重新核对。POST 使用 JSON 的 `draft`、`activate`、`validate`、`revoke` 操作。同一会话之外的版本请求会被拒绝。
